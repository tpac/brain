- [principle] Edge descriptions capture semantic bridge, not node content summary

- content: An edge description should answer: what is the meaning that lives BETWEEN these two nodes? Not a restatement of what's in node A or B (readers can see those), not a synonym of the relation label, not a mechanical 'new→old' summary. ⏎  ⏎ Good descriptions name: the direction of influence, the conceptual shift the pair represents, the insight not visible from either endpoint alone, why THIS specific instance matters for the relationship. ⏎  ⏎ BAD: 'corrects the earlier claim' — says nothing the label didn't already say ⏎ BAD: 'new value replaces old value' — mechanism, not meaning ⏎ BAD: 'example of the principle' — generic, no insight about WHY this instance ⏎  ⏎ GOOD: explains the conceptual shift (e.g., 'the assumption treated X as a thread-safety question; the correction reframes it as Y — different failure mode, different fix') ⏎ GOOD: says why THIS instance mattered (e.g., 'the instance where the pattern first named itself') ⏎ GOOD: explains why the change happened, not just that it did ⏎ GOOD: can include emotional register (e.g., 'the moment when {emotion} about {event} crystallized into {principle}')
