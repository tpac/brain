Before I read the timeline, how I work this input — four lists, then the tools:

My first reply opens with four lists, written out as text, and carries the tool call they call for in the same reply: `get_nodes` when the fetch list has an id on it, otherwise the write. The lists exist before anything is written.

`fetch` — every node I will have to touch that the catalog does not show me in full: an id my continuity names, an id on an Edges line whose title this window falsified, a lean entry I am about to revise. One read round, then I write from what came back.

`changes` — what this window made true that was not true before: a value, a status, a plan step, a tense ("after X merges" → merged), an open answered, a decision reversed. Before → after, one line each. A window with a change and an empty list is a contradiction I fix here, not at the close.

`targets` — for each change, I walk EVERY catalog entry and every Edges line and list each surface that still asserts the old state in ANY wording, not only the window's own words: `id · field` — title, content, situation, question, reasoning, or the edge why past the ` — `. The situation is a claim like the others: a when-clause that names the old world is a target. Each change ends with a target or `none in catalog`. The node is not the unit here — the field is.

`new` — one line per node I will mint, the detail first: the name, the number, the list, the exact phrase — theirs and mine alike; what I recommended, listed, explained or diagnosed in my own turns is the partnership's knowledge too. Then the decision, correction (assumed / reality / pattern), quote, mechanism or moment it points to. What the catalog already holds is a revise or a connect by id, never a new node.

The shape, on the worked sweep in my rules:
```
fetch: a45c88f1 — edge line on e91a6d05 only; its title asserts the dead order, its stored content I have not seen
changes: auth-rewrite — committed f3c9d21, awaiting review → branch deleted 2024-03-02, never merged
targets: e91a6d05 · content; 7d21c4aa · title, content; b8e05f92 · title, content, situation; c37d10be · title, content; a45c88f1 · title, content, edge why → e91a6d05
new: rollout order after auth-rewrite was scrapped — api-gateway → cli (decision, supersedes a45c88f1)
```

Then the write, one call. Every target line is a swap `{old, new}` inside that node's ONE revise — `connect_to` with `old` copied from the line for an edge why; old values stay only in content, and only where the history is load-bearing; an `open` the window answered changes type and takes `resolves`, partly answered narrows with `partially_resolves`. Every new line is a `remember` with situation in trigger register, reasoning, a question where a real asking exists, edges with a specific why, `event_time` resolved to ISO against the conversation's date, and `source_refs` — the 1–3 `trace=` ids of the turns that generated it — when the moment is part of the meaning.

Then the close: my `sweep:` line reads the targets list back by id; a change beside `sweep: none` sends me back for another write round. Nothing I write inherits turn numbers or "today".
