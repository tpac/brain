    Problem: Testing encoding quality disconnected from decoding quality gives misleading results. Encoding tests use fake brain tools (no real database), decode tests assume perfect encoding. Neither tests the roundtrip: Claude encodes → Arctic embeds → different Claude recalls.
    
    Solution architecture:
    1. Encoding tests: Non-deterministic by nature (LLM variance). Run N times, measure statistical distribution of richness, tool usage, connection patterns
    2. Frozen DB snapshots: After encoding, freeze database state as versioned fixture (brain_v5_snapshot.db). Deterministic foundation for decode testing
    3. Decode tests: Run against frozen snapshots. Exact reproducibility - same NDCG every time. Direct comparison across snapshot versions
    4. Roundtrip tests: Full encode→freeze→decode pipeline. Expensive (API calls) so only run when encoding changes

    - Separates deterministic (decode) from non-deterministic (encode) testing
