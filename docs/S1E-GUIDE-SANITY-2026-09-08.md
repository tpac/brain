## What the failures locate

The working procedure executed: all 18 encodes produced writes. The clearest
failure happened **before the write**, when a stored assertion was judged clean.
In V2 repeat 2, window 3, the poster was marked clean and omitted from the batch.
The final arc then said it was printed while the stored node still described
future printing. V3 repeat 1 marked the poster's reasoning clean even though it
said printing was not confirmed. Its check celebrated the selected updates
and left that assertion intact.

The same sequence appears in evidence handling: all six final passes promoted
the failed cover-sheet intervention into a categorical claim that the setting
was not the cause. The fixture explicitly says the test does not identify the
cause. The working lists already contain the overstatement, so successful
dispatch merely persists it. This is semantic judgment, not failure to call
tools or insufficient tool rounds.

There is also one useful recovery: V2 repeat 3 omitted the required audit
`reason` on the class revision. The tool rejected that operation; the next
round supplied it and the persisted class gained the third-lesson detail.
Keep this separate from the semantic failures and from the shared closure gate.

**Recommended next revision, not yet authored or approved:** change the existing
guide's comparison and verification procedure. A clean verdict should expose
the old assertion and its relationship to the new evidence; the closing check
should compare the resulting claims with that evidence, not only with the
model's own earlier list. This targets stale claims across fields and edges,
promise-to-accomplishment inflation, uncertainty-to-refusal inflation, and
failed-intervention-to-causal-exclusion inflation. Revise the existing worked
example to demonstrate that shape with unrelated content. Do not add a separate
pile of reminder sentences or tune to umbrellas, posters or PDF object numbers.

The compact arm remains a useful base to consider: it did not lose the basic
facts in this sequence. This cell combines compression, revisions and cues, so
it cannot assign credit to any one of them. Preserve the five frozen arms;
author any next revision under a new identity. Wider independent corpora and
the historical per-item comparison remain necessary after this sanity stage.

  the actual run clock, September 9 UTC. Those rendered dates are harness
  context, not model-authored errors. All six sequences nevertheless explicitly
  wrote Saturday as September 13 (Sunday), rather than September 12. Report
  the observed mismatch, without claiming its cause. Fix clock coherence in
  a newly versioned fixture before interpreting further temporal comparisons.
- Timeline turns use `<other>` without an explicit Oren speaker attribute.
  Oren is established by seeded project context; the large background catalog
  contains Tom. Make participant identity explicit in a new fixture version
  before treating attribution as a clean scored dimension. Do not rewrite the
  inputs of this completed cell.
- Catalog selection is constructed; targets are already present. Zero reads
  therefore do not test missing-ID retrieval or solve the residue-rendering gate.
- The guide can write redundant new nodes while also revising existing ones

  includes that actual continuity. We distinguish the model's newly emitted
