# Oracle Audit Spec — Hindsight Golden-Set Recall Diagnostic

**Status:** draft spec for review (2026-06-04). Not built. Design conversation artifact.
**Owner thread:** "how do we diagnose" → "measure Anchor against its own needs" → this.

## 1. Purpose — what it diagnoses

Find **silent recall failures**: turns where a node that would have been *genuinely useful*
existed in the brain but didn't surface — and **localize each to a pipeline stage**
(surface / recall / encode). The output is the **failure distribution we currently lack**:
we can count loud failures (daemon down, timeouts) but have no denominator for the silent
class Tom feels but can't see.

This is a **diagnostic, not a benchmark**. It is not a score to maximize. It exists to find
*owned, localized* failures so we can decide whether anything is worth building —
**diagnose before add** (the lesson of the consolidation/confidence root-outs).

It is the automated form of **Lens B** from the three-lens trace audit (`ba71ea5d`).

## 2. Core concept — two-retrieval divergence

Compare two retrievals over the same turn and localize the gap:

- **Production retrieval** — what *actually* surfaced (from traces).
- **Oracle golden set** — what Opus, reading the conversation **before and after** the turn,
  judges *should* have surfaced.

**The non-negotiable invariant:** the oracle must **out-recall production** (independent, wider
reach). If the golden set is generated by *the same* recall, the audit is circular — it can only
ever catch *surface* misses and is structurally blind to *recall* misses (if production recall
missed it, a same-recall golden set misses it too). The oracle is a *different, stronger* process.

## 3. The golden bar — **value, not deficiency-repair** (Tom, 2026-06-04)

A node is **golden** if surfacing it would have constituted **recognition** — Anchor seeing the
relevant fact, the connection, the continuity thread, or the applicable scar that a stateless
stranger wouldn't. Recognition is *itself* the value: a surfaced thought is the brain recognizing
what matters here, not a means to patching an answer. So a node is golden **even when the actual
response was fine without it.** — Tom: *"thoughts are recognition."*

> Rejected framing: "golden iff using it would have repaired a deficiency in the response."
> Too narrow. Thoughts, reflections, resonance, and continuity have value that is not
> deficiency-repair. — Tom: *"thoughts are not measured by repairing deficiency."*

The line we **do** hold is **value vs. inert/topical noise** — so over-surfacing is still scored
against (symmetric scoring). The distinction the oracle makes is *value-add vs. noise*, not
*deficiency vs. no-deficiency*.

**Consequence:** the **dry-Claude lens drops from gold-anchor to side signal.** Dry-Claude tests
"was the response deficient without the brain" — exactly the deficiency frame we rejected as the
*measure*. It stays as a *complementary* lens (does the brain change behavior at all), but the
golden set is judged on value directly, by the oracle.

**Graded + multi-reason output.** Each golden node carries:
- `value_type` ∈ {fact, connection/insight, continuity/thread, correction/scar, identity/voice, context}
- `strength` (e.g. 1–3: nice-to-have → important → load-bearing)
- `why` (one line)

**Recency exception (Tom, 2026-06-04):** a node that *was already surfaced in a recent prior
turn* is **not** a miss if it didn't re-surface — re-showing the same node every turn is noise,
not recognition (mirrors the existing synaptic-fatigue suppression). The golden set excludes
nodes shown in the last few turns. *"Surface it if we have it — unless it just surfaced a moment
ago."*

## 4. The knowable-at-T vs. hindsight-only flag (the prior-art lesson)

The oracle sees the future of the conversation. That makes it powerful **and** introduces a bias
we must control: some "useful in hindsight" info was **not yet cued** at turn T — the need only
appeared *later*. Penalizing the brain for not predicting the future is wrong.

So every golden node is tagged:

- `knowable_at_T = true` — the need was **already cued** by the prompt + prior turns. A miss here
  is a **fair, fixable retrieval failure.**
- `knowable_at_T = false` — only the **after**-context reveals the need. A miss here measures
  **headroom / regret** vs. an omniscient retriever — a *ceiling*, not a fixable failure.

Report the two rates **separately**. (RMM sidesteps this by using *cited evidence* as its
hindsight signal — leak-free but conservative; our full-future oracle is stronger but must carry
this flag. See §10.)

## 5. Inputs / data sources (all owned)

| Need | Source |
|---|---|
| Prompt + actual response | `trace_events` `ref_type='user_message'` (metadata: full `content` + `recall_chain`) / `assistant_message` |
| Candidates (what recall fetched) | `trace_events` S1R chain, `ref_type='recall'` |
| Surfaced/selected (what reached `additionalContext`) | `trace_events` S1R chain, `ref_type` ∈ {`surface_selected`, `additionalContext`} |
| Node existence + content at T0 | `brain.db` nodes, `created_at` filter |

> **Note (verified 2026-06-04):** `message_stream` (`b619aafc`) is **empty / deprecated** —
> migrated-and-killed (`8ec8327a`). All recall provenance now lives in `trace_events` S1R chains.
>
> **Note (verified 2026-06-04, B1-13 probe) — keying bug:** `recall_chain`
> (`s1r-{short_session}-{stop}`) is **NOT a unique turn key**. The `stop` counter resets on
> resume/relaunch, so one chain id maps to multiple turns within a session (observed:
> `s1r-2df9bf99-1` = an S2-community turn on 04-16 **and** the call-stack turn on 04-17, same full
> `session_id`). **Key each turn by the `user_message` `trace_id` (unique) and disambiguate its
> recall/surface/additionalContext rows by matching `created_at`** — never by `recall_chain` alone,
> or localization silently attributes the wrong turn's surfaced set.

**Live-brain safety:** read-only audit → dispatch through the daemon (TCP). **Never** spawn a
second `Brain(db_path=...)` writer against live `brain.db`. Heavy replay → `IsolatedBrain` copy.

## 6. Time-correct reconstruction (and its honest ceiling)

- Restrict the oracle's reachable pool **and** golden set to nodes with `created_at < turn_time`.
- **Contamination guard:** exclude nodes encoded *in the same session or after* the turn — the
  EX.CO / pasta-carbonara trap (a node encoded *because* of this turn would leak).
- **Honest ceiling:** `created_at` gives *existence*, but nodes are later **revised** and
  **re-embedded**. So "what recall would have returned at T0" is *approximate* — content/embedding
  at T0 ≈ now. This specifically **blurs recall-miss vs. encode-miss** attribution. v1 accepts the
  approximation and flags it; true fidelity needs node version history (not currently kept).

## 7. The oracle (Opus)

**Input:** turn prompt + `N` turns before + `M` turns after (hindsight window) + a **wide candidate
pool** (high-K recall + query reformulations, `created_at<T` filtered) — and optionally a broader
structural scan, so nodes *beyond* production's cosine+FTS reach are visible (else recall-misses
are undetectable).

**Output (structured):** `golden = [{node_id, value_type, strength, knowable_at_T, why}, ...]`.

**Rubric:** judge *value to this moment* (§3, looser than deficiency); mark `knowable_at_T` (§4).
Blind to what production actually surfaced (avoid anchoring). Multi-vote for stability.

## 8. Comparator + localizer

For each golden node:

| Condition | Verdict |
|---|---|
| ∈ surfaced | **hit** |
| ∈ production candidates, ∉ surfaced | **surface miss** |
| ∉ candidates, ∈ oracle's wide retrieval | **recall miss** |
| reachable only by scan / no query finds it | **encode/store miss** |

Plus the precision side: **surfaced ∉ golden → over-surface (noise).**

## 9. Metrics / output

- **Per-turn:** golden hits, misses by stage, over-surfaces.
- **Aggregate:**
  - **Fair miss rate** = misses among `knowable_at_T` golden nodes (the actionable number).
  - **Headroom miss rate** = misses among hindsight-only golden nodes (ceiling, not a target).
  - **Stage distribution** of misses (surface / recall / encode) — tells us *where* to look.
  - **Over-surface rate** (precision / noise).
  - **Brain-irrelevant rate** = turns with empty golden set — *the fishbowl number* (how often the
    brain even gets a chance to matter). High on brain-dev turns is correct, not a bug.

## 10. Validation-first protocol (the instrument can lie)

Every measurement instrument we've built has lied to us once, and the lie pointed at the wrong fix
(bucket labels → `1febec26`; corrupt gold → `17037bd5`). The oracle is a judge, and judges are
"prompt-sensitive, unstable, prone to self-preference bias" (ARES). So **before trusting any
aggregate:**

1. **Manual calibration.** On ~K turns, a *human* golden set is produced and compared to the
   oracle's. Measure agreement. Scale only if agreement is high.
   - **Tom is the calibration anchor** for ~3 turns — the "measure me through *your* eyes" point.
     The oracle must match Tom's sense of useful, not just Anchor's (Anchor judging Anchor is the
     contamination risk).
2. Blind judging; multi-vote oracle; manual spot-check of localizer verdicts.

**First deliverable = the calibration pass, not the full system.** If the oracle can't reliably
match human judgment on a handful of turns, we've found the real bottleneck before building on sand.

## 11. Cost / sampling

The oracle (Opus + wide context + multi-vote) is the expensive part → **sample, don't run
continuously.** Corpus choice *is* the experiment (§9 brain-irrelevant rate): memory-relevant turns
(cross-session / personal / correction-adjacent) for signal; random for the fishbowl rate.

## 12. Boundaries — what this is NOT

- Not always-on; a sampled offline diagnostic.
- Not a score to maximize.
- **Recall-reach ceiling:** Lens-B/oracle finds misses only among nodes *some* retrieval reaches.
  A node encoded so badly nothing retrieves it is invisible even to the audit — deepest
  encode-misses are under-counted.
- Dry-Claude (side lens) is impure: it sees prior turns that were already brain-shaped, so it
  measures *marginal-this-turn* value given a brain-shaped history, not zero-brain-ever.

## 13. Prior art / lineage

- **RMM — "In Prospect and Retrospect"** (arXiv 2503.08026, Mar 2025): retrospective reflection =
  hindsight-from-what-was-cited. Closest published analog. We differ: **audit, not online
  improvement**; **value-judge, not citation** (stronger signal, needs the §4 flag).
- **LongMemEval** (2410.10813) / **LoCoMo**: judge protocol (GPT-4o >97% human agreement),
  Recall@k / NDCG@k on exposed retrieval traces, 5 ability categories incl. **abstention**.
- **ARES** (NAACL 2024): calibrate the judge against human labels → §10.
- **Counterfactual attribution** (2412.10571): leave-one-out evidence removal = the dry-Claude lens.
